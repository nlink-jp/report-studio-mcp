# report-studio-mcp

エージェントが書いた Markdown のレポート原稿（文章、グラフのデータ、構成図の定義）を受け取り、
組版した PDF と編集できる Word 文書（.docx）を呼び出し側の作業ディレクトリに出力する MCP サーバです。外部のサービスやブラウザには
頼りません。組版は macOS 自身の機能（Core Text・Core Graphics）で行い、日本語の禁則処理が効き、
フォントは使った文字だけが埋め込まれます。

[English README](README.md)

## なぜ

gem-agent や lagent で調べた結果は、Markdown の応答として手元に残ります。人に渡すには手で
体裁を整える必要があり、グラフや構成図を入れるのはさらに手間がかかります。report-studio-mcp は、
エージェントが書いた原稿から、そのまま渡せる文書を作ります。

## 受け付けるもの

- **普通の Markdown**: CommonMark 0.31.2 に、GitHub の表・取り消し線・チェックリスト・自動リンク、
  脚注、注記（`> [!NOTE]` など）を加えたもの。任意の front matter で、題名・副題・作成者・日付と、
  全ページに印字する区分（「社外秘」など）を指定できます。
- **データからのグラフ**: ` ```chart ` ブロックに JSON を書くと、サーバが描きます。棒（縦・横、
  グループ・積み上げ）、折れ線、散布図。
- **構成図**: ` ```mermaid ` ブロック（flowchart、sequence、ER、state、gantt、pie、mindmap）を
  [mermaid-render](https://github.com/nlink-jp/mermaid-render) で描きます。描けない図はソースを
  載せて警告します。
- **画像**: 作業ディレクトリの中の PNG・JPEG ファイル。

## 出力

- **PDF**: ヒラギノ（またはプロファイルのフォント）、ページ番号、ヘッダーの区分。表紙や目次を付けると、
  題名のページと、各項目から見出しへ飛べる目次が入ります。
- **Word（.docx）**: 同じ内容を、プロファイルから作った Word のスタイル（見出し・本文・表・引用・コード・
  キャプション）で書き出します。脚注は Word の脚注、番号付きリスト、目次フィールド、同じ画像とグラフ。
  受け取った人が Word で体裁を直せます。

## 改ページ

ほとんどの文書では、改ページのために何かを書く必要はありません。

- 見出しと、**キャプション**とその本体は、次に続くものの冒頭と同じページに置きます。キャプションとは、
  太字だけの段落、または `表1：` `図1：` `Table 1:` `Figure 1:` で始まる段落で、表・グラフ・図・画像・
  コードの直前に書いたものです。間に斜体だけの注記の行（`*出典: ...*`）があれば、それも含めます。
- 見出しは途中で改ページしません。段落の 1 行だけがページに取り残されることもありません。
- ページの残りに収まらないグラフ・図・画像は、縮めて収めるか（70% まで）、キャプションごと次のページへ
  送ります。
- **表のセルの数値は途中で折り返しません**（`1,234,567`、`12.34%`、`▲１２．３４％`、`192.168.10.25`、
  `100mg`、`US$1,234`）。英字が数字より前にある識別子（ハッシュ値、UUID、`CVE-2024-12345`）は数値として
  扱わず、折り返すことがあります。数値を保てないほど表の幅が足りないときは、警告 `cell_token_split` が該当する列を示します。
- `break_before` で章を新しいページから始めます。`h2`（`formal` の既定）では、本文の後に来る一番外側の
  `#`・`##` 見出しが新しいページから始まります（見出しが続くときは 1 回だけ。ページの先頭では切りません）。
  `h1` は `#` だけ、`none` は改ページしません。プロファイルか front matter で指定します。

それ以外は 2 つの指示で補えます。本文の一番外側に、HTML のコメントだけの行として書きます（普通の
Markdown のビューアでは何も表示されません）。`keep-with-next` が効くのは段落・見出し・コード・グラフ・
図・画像・区切り線で、表・リスト・引用・注記・生の HTML には効きません。

```markdown
<!-- pagebreak -->
<!-- keep-with-next -->
```

## プロファイル

同梱は 3 つです: `standard`（A4、ヒラギノ角ゴ）、`formal`（表紙・目次、本文はヒラギノ明朝、余白を広く、
章ごとに改ページ）、`compact`（余白と文字を小さく）。運用者は `config.toml`（`$XDG_CONFIG_HOME`・`~/.config`・
`~/Library/Application Support` の `report-studio-mcp/` の下）にプロファイルを足せます。同梱のどれかを
土台に、用紙・余白・フォント・文字の大きさ・色・グラフの配色・表紙・目次・表紙のロゴ・章の前の改ページを
上書きします。

```toml
[profiles.customer]
extends = "formal"
margin_mm = 22
toc_title = "目次"
logo = "~/Pictures/logo.png"
```

原稿はプロファイルを名前で選び（front matter の `profile:` か、引数 `profile`）、表紙と目次（`cover:`、
`toc:`）と章の前の改ページ（`break_before:`）を切り替えられます。設定ファイルは [nlink-jp/toml](https://github.com/nlink-jp/toml) で厳格に読むので、
知らないキーはエラーになります。

エラーにするのは、出力が間違ったものになる場合（グラフの JSON の誤り、画像が無い、上限超過）だけです。
それ以外は、原稿の行番号つきの警告として返します。詳しい使い方はサーバの `get_usage` ツールにあります。

## ツール

| ツール | 役割 |
|---|---|
| `get_usage` | 使い方の全体（原稿の書き方、グラフの JSON、上限、エラーと警告） |
| `render` | `{work_dir, workspace_id, source}` → `<work_dir>/<workspace_id>/out/<原稿のパス>.pdf` と `.docx`（`formats` で片方だけも可）。ページ数と警告も返す |

`work_dir` はすべての呼び出しで必須で、既定値はありません。呼び出し側が読み戻せる絶対パスの
ディレクトリを渡します（組織 ADR-021）。

## 安全のための設計

- 読み書きはすべて作業ディレクトリの `os.Root` を通します。開いたファイルはカーネルが示す実際のパスで
  [pathguard](https://github.com/nlink-jp/pathguard) の床に照らします。読むのは通常のファイルだけで、
  出力は新しい一時名で書いてから名前を付け替えます。
- クリックできるリンクは `http`・`https`・`mailto` だけです。無害化された指標は書かれたまま出します。
- .docx の文書プロパティに入れるのは題名と作成者だけです。PDF の文書情報には題名と作成者のほか、
  Core Graphics が必ず書く作成ソフト（macOS の版）と作成日時が入ります。

## 制約事項

- **.docx は Microsoft Word では確認していません。** ECMA-376（第 5 版、Transitional）に沿って書き、
  部品ごとに確かめています（XML の整形式、Content Types、関係、脚注、番号付け、しおり）。また、
  Pages 15.4 と LibreOffice 26.8 で警告なく開け、すべての要素が表示されることを確認しました。
  Mac 版・Windows 版の Word は手元に無かったため、Word で修復の確認なしに開けるか、Word でどう
  表示されるかは確認していません。
- .docx の目次は、見出しをページ番号なしで並べます。Word でフィールドを更新すると番号が入ります。
- .docx では、改ページの規則を段落の性質（次の段落と分離しない、段落前で改ページ、孤立行の制御）として
  書き、改ページは読む側のソフトが決めます。Word でどう改ページされるかは確認していません。Pages と
  LibreOffice での改ページは人が確認しました。数値の列は Core Text で測った数値の幅を取りますが、全角の数字
  （`１２３`）は狭い列で折れることがあります。
- 文章は左から右に組みます。右から左に書く言語の段落は、文字は保ちますが左から右の行として組みます。

## 動作環境

Apple Silicon の macOS 26 以降。上に挙げた nlink-jp のモジュールのほかに外部の依存はありません。
